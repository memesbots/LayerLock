# LayerLock Engineering Audit - 2026-07-26

## Scope

This review covers the self-contained LayerLock v7 HTML application, its container
format, password and key-file flows, Aztec encoder/decoder integration, compact
imports, export paths, release tooling, tests, and GitHub Pages workflow.

The release manifest is regenerated whenever the artifact changes.

## Threat Model

LayerLock is intended to protect notes against an attacker who obtains the exported
container but does not know the master key, layer password, or optional external key
file. The attacker is assumed to know the complete source code and format. Security
must not depend on hiding the implementation.

The model does not protect against a compromised browser, operating system, keyboard,
clipboard manager, malicious replacement of the HTML before use, coercion, or loss of
all recovery material.

## Resolved Findings

| Severity | Finding | Resolution |
| --- | --- | --- |
| Critical | Unbounded decompression could exhaust memory. | Length-framed compression, strict output caps, strict UTF-8, and bomb tests. |
| High | Oversized images and compact payloads could trigger expensive work. | Byte, dimension, pixel, container, and text limits are enforced before scanning. |
| High | Generated key files could be used before the download was safely retained. | The downloaded file must be selected again and matched by digest before creation. |
| High | Stress verification accepted optical detection without authenticating content. | Every candidate now authenticates the container and decrypts all expected layers. |
| High | Release dependencies were not fully reproducible. | Exact vendored versions, source hashes, licenses, a lockfile, and verification gate were added. |
| Medium | Inline scripts required a permissive CSP. | Release tooling computes exact script hashes; `connect-src 'none'` blocks networking. |
| Medium | Scanner handed very large images directly to WebAssembly. | A bounded fast pass and bounded thorough pass reduce latency and memory pressure. |
| Medium | Weak-password feedback overstated entropy. | Conservative policy labels replace pseudo-entropy estimates; common patterns are rejected. |
| Medium | ZIP settings leaked unnecessary structural metadata. | Timestamps, names, layer counts, and key-file-use indicators are omitted. |
| Low | Randomized ordering had modulo bias. | Rejection sampling now produces unbiased indices. |
| Low | Non-canonical variable integers were accepted. | Canonical encoding is required and tested. |

## Verification Performed

- AES-GCM ciphertext and tag tampering are rejected.
- Equal plaintext and passwords produce different ciphertext due to random salts/nonces.
- Master-key and layer-password validation rejects weak, reused, and normalized duplicate secrets.
- Native and fallback decompression honor the same post-decompression size limit.
- Compact, optical, image-header, and decompression resource limits have negative tests.
- Aztec round trips cover 90/180/270-degree rotation, white screenshot background, and downscaling.
- English and Russian static/dynamic UI strings have smoke coverage.
- `outputs/sigil-vault.html` and `dist/index.html` must be byte-identical.
- The release verifier checks CSP hashes, dependency hashes, checksum, and network fallback removal.
- Manual desktop browser QA covered creation, authenticated verification, settings controls, and console errors.

## Residual Risks

1. This is an engineering audit by the implementation agent, not an independent
   third-party cryptographic certification.
2. Argon2id and AES-GCM are established primitives, but their composition and this
   JavaScript implementation have not received formal verification.
3. Real camera and print reliability needs a maintained corpus across iOS Safari,
   Android browsers, printers, paper damage, glare, perspective, and low light.
4. Browser JavaScript cannot guarantee that plaintext has been physically erased from
   memory, swap, screenshots, clipboard history, or crash reports.
5. GitHub Pages protects transport with HTTPS but not against repository/account
   compromise. Critical use should rely on a separately stored HTML and verified hash.
6. Losing the optional key file makes protected containers unrecoverable by design.
7. Matrix dimensions still reveal an approximate upper bound on payload size.
